# Chat Creation Flows

일단 프론트에서 채팅방 만들면
mysql에 먼저 저장하고 어차피 채팅방 목록도 mysql에서 조회하니까 트랜잭션으로 다 묶어서 실행하고
프론트에서 상세 페이지로 이동 시켜도 됨

채팅방 미리보기 카드에는 채팅방 제목, 마지막 메시지 내용, 보낸 시간, 안 읽은 메시지 개수가 필요함.

일단 고려해야 할 거는 채팅 메시지는 mysql이 아니라 scylla에 있기 때문에

메시지 내용, 시간, 안 읽은 메시지 개수를 구할 때 mysql에서 계산할 수가 없음.

읽은 시간을 기록하고 마지막으로 읽은 시간 이후 메시지 개수를 구하는 건데
scylla에서 계산해서 보내줘야 함.

조회가 너무 복잡해지니까 
차라리 시간 기반 필터링이 아니라

비정규화 해서 유저별 채팅방 미리보기 카드 테이블을 만들고
여기에 메시지 내용, 시간, 메시지가 올 때마다 카운트를 증가시키는 식이 나을 듯

읽으면 0으로 바꾸꼬 

이럼 fanout 비용이 발생할텐데 일대일 채팅이라 상관 없음.

그럼 mysql에는 진짜 초기 채팅, 재판 데이터만 있고

scylla에서 쓰기는 동기
목록은 비동기로 비정규화 해서 써야곘는데

채팅오면 어디 채팅방인지만 알 수 있음.
mysql에서 채팅방 조회해서 그 채팅방에 참여중인 유저 찾고
웹소켓 쏴야 함.

이건 한 번 보낸 놈은 카페인에 걸어 놓고 굳이 다음 조회 필요 없이 해야겠는데
